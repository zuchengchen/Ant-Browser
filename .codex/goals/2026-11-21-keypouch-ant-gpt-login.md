# 从 key 打开 Ant 实例并一键登录 GPT

## Goal 模式目标

按 `/home/czc/projects/working/Ant-Browser/.codex/goals/2026-11-21-keypouch-ant-gpt-login.md` 完成单条 key 记录到 Ant 实例的凭据同步、本地 GPT 登录和加密迁移。全部必需验收通过后才可完成，遇到停止条件先询问用户。

## 完整任务

### 目标

用户在已登录的 key 记录页点「创建并打开 Ant 实例」，再在对应实例的 Chromium 工具栏点一次「登录 GPT」，即可使用该记录的邮箱、密码和验证器动态码登录。整个过程无需在实例内登录 key、复制授权码或重新选账号。

### 背景

key 仓库是 `/home/czc/projects/working/KeyPouch`，服务部署在独立服务器。Ant 仓库是 `/home/czc/projects/working/Ant-Browser`。现有打开流程已支持设备配对、签名请求、记录与实例关联、分组和窗口回执，交接内容主要是邮箱与分组。现有「登录 GPT」扩展另有插件授权和网页会话两种入口。Ant 的克隆按钮当前只复制配置，实例包已有用迁移密码加密 Cookie 的能力。实施以当前工作区为基线，保留 Ant 已修改的跟踪文件和未跟踪的插件源码。线上运行版本尚未核实。

### 已选方案

沿用 key 网页会话和首次电脑配对。每次从 key 打开时，通过配置的 HTTPS 站点，将所选记录的凭据同步给对应实例并在本机加密保存。用户点击扩展后才发起 GPT 登录，遇到验证器挑战时由本机生成当期动态码。此后即使 key 暂时不可达，也可以用已保存的凭据登录。撤销配对阻止后续同步，已交付的本地副本仍会保留。

### 发现阶段的决策

- 原待定 → 已接受的更新规则。从 key 再次打开时刷新原绑定实例。密码或种子被清空时也清除本地旧值。克隆和迁移得到的副本独立保存复制时的内容。
- 原待定 → 已接受的克隆规则。来源实例有凭据时，在现有克隆窗口提供默认未勾选的「同时复制 GPT 登录凭据」。勾选后副本可直接使用「登录 GPT」。模板创建和普通配置复制不会把账号带给新实例。
- 跨电脑复用实例包的迁移密码，加密保护新增的凭据条目。新电脑用迁移密码导入后即可使用该账号，无需 key 会话或重新配对。普通 ZIP 和无迁移密码的备份不携带这份凭据或恢复它所需的密钥。

### 范围

- key 只向本次打开请求对应的有效配对设备交付该条记录。Ant 窗口状态、打开票据查询、旧版打开响应和深层链接均不携带密码或种子。状态提示能区分窗口已打开、凭据已同步及同步失败。
- Ant 核对站点、记录和目标实例后再保存，沿用已有实例首次关联确认。更新具有原子性，重复点击、并发请求和中断重试均不会串号或留下混合凭据。使用受本机用户保护的密钥。密码、种子及可复用的解密材料不得写入明文配置、共享扩展目录、剪贴板或日志。
- 已同步的实例从工具栏直接使用本地凭据。保留未同步实例的既有登录入口、账号核对和官方登录页边界。邮箱验证码、人机验证及第三方登录交由用户完成。保留实例选定的代理连接栈。
- 接入现有克隆、导出和导入入口。验证迁移密码与条目完整性后再写入目标实例，兼容旧实例包。补充两个项目相关测试、使用说明、升级顺序和回退步骤。Ant 在当前工作区交付，key 按仓库规则只提交本任务改动并推送到 `origin/main`。

### 范围外

生产服务器部署、真实 GPT 账号验收、正式发布和打标签。

### 验收

在本次工作树上运行以下命令。报告目录由本次运行创建，Shell 保留每一步的退出状态。

```bash
set -euo pipefail
goal_reports=$(mktemp -d)

cd /home/czc/projects/working/KeyPouch
KEYMEMO_VERIFY_DIR="$goal_reports/key" bun run ci >"$goal_reports/key-ci.log" 2>&1

cd /home/czc/projects/working/Ant-Browser
npm --prefix frontend ci >"$goal_reports/ant-install.log" 2>&1
npm --prefix frontend run build:clean >"$goal_reports/ant-build.log" 2>&1
test -s frontend/dist/index.html
go test -count=1 -tags webkit2_41 -json ./... >"$goal_reports/ant-go.jsonl" 2>"$goal_reports/ant-go.stderr"
node --test --test-reporter=junit frontend/scripts/test-keypouch-gpt-*.mjs >"$goal_reports/ant-node.xml" 2>"$goal_reports/ant-node.stderr"
```

1. 将每项必需场景对应到具体测试名或实际操作记录。检查当次 Go、Playwright 和 Node 的结构化报告，确认相关用例被发现、执行并通过。构建产物必须能从本次干净构建加载。区分产品失败和环境故障。必需用例跳过、零执行、报告缺失或不可解析均不能计为通过。若新增自定义报告匹配器，用一个真实失败样本和一个含相似文字的正常样本校准，格式允许时覆盖多行。
2. 用隔离的 key 测试服务、Ant、实际 Chromium 扩展和合成登录页走通两个按钮。准备两条内容不同的合成记录。每次验证登录前使测试站会话失效并保留实例凭据，核对测试页收到所选账号的邮箱、密码及独立计算的当期动态码，确认登录完成后显示对应邮箱。重启 Ant 和实例并阻断到 key 的连接，再从工具栏完成同样操作。记录脱敏结果。
3. 覆盖凭据轮换和清空、重复打开及中断重试、错误设备和失效请求、已登录其他账号、缺少凭据及需要手动验证。核对实际实例和结果，普通窗口回执不能代替凭据就绪。验证旧客户端打开流程及原有插件授权路径，并用本次合成密码和种子检查实际打开链接、旧版打开响应及日志。
4. 在来源上分别勾选和取消克隆选项。用独立安装数据和本机密钥模拟第二台电脑，验证正确迁移密码导入后可登录，错误密码或损坏包不会覆盖现有凭据，旧包仍可导入。检查普通导出和备份的实际归档条目、解包内容及导入结果，并用正确解密的受保护条目作为对照。
5. 其余验收通过后，提交并推送 key 的本次改动。在 key 仓库运行 `git fetch --no-tags origin main`，再用 `git merge-base --is-ancestor <本次提交> FETCH_HEAD` 核对远端已包含该提交。

### 风险与上线

先升级 key，再升级 Ant。混用新旧版本时，只有确认凭据已保存才能提示同步成功。记录旧版回退办法及已迁移副本的保留方式。如涉及数据库迁移，沿用仓库的追加迁移和备份规则。说明迁移密码保护的具体条目，以及 key 端改密或撤销配对对独立副本的影响。

### 停止条件

无法可靠限定领取设备、记录或使用凭据的实例，或只能以明文保存时，先询问用户。若必须覆盖 Ant 已有未提交改动、操作生产服务或使用真实账号才能继续，先确认。对可恢复的构建和验证故障先诊断重试，仍无法取得必需证据时报告缺口。

### 子代理设置

`enabled: true`，`parallelism: max_available`，`model: inherit`，`reasoning_effort: inherit`，`fallback: serial_if_unavailable`。可通过 `spawn_agent` 派发，`list_agents` 和 `wait_agent` 查看和收集结果。使用 `fork_turns=all` 继承设置。规划时共 4 个槽位，主代理占 1 个，执行时重新核对可用容量。可分别分配 key 的交接接口、Ant 的实例存储与迁移、扩展登录与浏览器验证。子代理只返回互不重叠的隔离补丁或审查结果，主代理负责共享文件、集成、验证及目标状态。派发能力不可用时串行执行，子任务失败需查明并补完。
