## 完整任务

### 目标

在 Ant-Browser 中提供唯一一套“实例分组”：用户可以在实例列表内新建、重命名和删除分组，维护子分组，为一个实例选择多个分组，并批量加入或移出分组。旧标签和旧分组关系完整迁移，重启后持久保存；移除重复的标签管理入口。

### 背景与约束

项目根目录为 `/home/czc/projects/working/Ant-Browser`。当前实例采用单个 groupId 与多个 tags，已有分组层级，但列表没有完整的分组管理入口。只读检查时有 60 个有效实例、10 种已使用标签、0 个实例分组；执行时重新核对，不能把这些数量当作永久常量。

当前系统包为 ant-browser-bin 1.9.0-2，应用版本为 1.9.0。保留尚未提交的“关于软件”去个人信息改动、代理初始化等待修复及其他现有工作。

遵守 AGENTS.md 的界面、fork 和版本规则。短表单使用弹窗，复用现有组件，保持保存、取消和返回行为一致。引用的 Windows 共享界面技能文件在已检查位置不可用，依据仓库内明确规则和现有组件实施，不假称已读取这些文件。代理连接栈说明文件缺失时仍遵守 AGENTS.md 中的明确规则；本任务不涉及代理连接逻辑。

### 范围

1. 建立唯一的多对多分组归属模型，更新数据库、管理器、内存快照、后端接口、Wails 绑定及前端类型。旧字段仅承担兼容职责，不能形成第二套独立分类事实。
2. 迁移旧 groupId 和 tags，包括回收站实例的归属；保留实例身份、配置和浏览器数据。迁移中途失败不留下部分结果，重启不会重复建组。
3. 实现分组树、父子关系、空分组保存、名称和循环校验、新建/重命名/删除确认，以及单实例和批量的多个归属编辑。错误应给出真实原因，失败不显示虚假成功或半完成状态。
4. 筛选与计数遵循批准的去重规则，活跃列表不计入回收站实例。编辑后及时刷新，旧筛选缓存可恢复为合理的对应状态。
5. 合并标签管理导航、表单与筛选入口，旧页面地址转到新的实例分组入口。更新相关使用说明和公开 API 示例。
6. 覆盖旧接口的 tag/tags/groupId、实例复制、删除与恢复、实例包导入导出、整库备份恢复和合并；新格式完整携带多个归属，组 ID 重映射保持关系和层级。实例包保留所选实例的相关分组及祖先；整库备份保留全部分组，包括空组。
7. 旧接口不能因只认识单个 groupId 或标签而静默清除额外归属。无法唯一解析的请求应明确失败；实际用户数据的无损转换无法确定时按停止条件处理。
8. 分组写操作保持事务完整，处理并发或重复操作，数据库与内存一致；避免按实例逐一额外查询导致列表读取明显退化。
9. 添加必要的行为测试和验收脚本，生成本次构建与验证记录；通过后构建本地安装包并替换系统版本，检查启动与文件一致性。

### 风险、上线与回滚

主要风险是分类关系丢失、重名歧义、旧接口覆盖多个归属、备份组 ID 映射错误和迁移中断。用事务、稳定 ID、明确冲突反馈、兼容测试及一致备份控制这些风险。

保留旧安装包/程序和迁移前数据库、配置的可恢复副本，先在隔离环境验证真实数据副本，再安装已经验证的本地包。应用数据库首次迁移前必须有一致且验证可读的备份；不得仅复制一个可能遗漏 WAL 内容的数据库文件作为一致备份。

应用数字版本保持各文件一致，本地包使用可区分的新版本或递增包修订号。更新说明记录功能变化与旧标签迁移行为。现有系统替换安装授权继续有效，正常流程不再重复请求安装许可。

回滚按旧程序与迁移前数据配套进行，并在隔离环境验证恢复；不能把只降级程序当作可靠回滚。若升级后产生新数据，不静默覆盖这些写入，先说明冲突并请求处理决定。

- 实际用户数据出现无法唯一、无损映射的重名或关联冲突，需要合并、删除或改变含义才能继续。
- 一致备份或恢复验证失败，或实施必须丢弃实例、配置、浏览器数据或已有分组归属。
- 旧接口兼容必须牺牲已批准的数据完整性要求，且无法通过明确拒绝有歧义的请求解决。
- 回滚必须覆盖升级后新增数据。
- 需要实质改变已批准的范围、验收或风险处置。

出现上述情况时保留现场并询问，不猜测、不把未完成目标标记完成。普通代码、测试或环境错误应先在范围内定位修复；验证失败不能被当作成功。
