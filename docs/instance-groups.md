# 实例分组

实例分类统一使用“实例分组”。同一个实例可以加入多个分组，分组可以平铺，也可以建立子分组。原来的实例标签管理地址 `/browser/tags` 会转到实例列表并展开分组树。

## 使用方法

- 在实例列表左侧点击“新建分组”，或点击某组旁的加号建立子组。重命名弹窗也可以调整父组。
- 点击实例旁的分组名称或“未分组”，勾选多个归属；编辑实例配置时也支持多选。
- 勾选列表中的实例，用“加入分组”“移出分组”批量修改指定归属。其他归属保持不变。
- 点击父组会显示本组和所有子组的实例；一个实例只显示、计数一次。“未分组”表示没有任何归属，回收站实例不计入活跃列表。
- 同级名称唯一，不同分支可以同名；选择器和实例详情显示完整路径。空组会保留。
- 删除组保留实例及其他归属，直接子组提升一级。提升后同级重名时整项操作失败，先改名再删除。删除操作需要确认。

快速启动、插件实例选择、自动化和启动 API 使用相同的归属与后代匹配规则。自动化脚本自身的描述标签及代理分组属于其他功能，不是实例分类。

## 旧数据迁移

数据库版本 34 创建 `browser_profile_groups` 多对多关系表。原 `group_id` 关系和每个旧标签取并集：旧标签映射到根组，已有同名根组可以复用；原组 ID、父子关系、空组、回收站归属保持。重复启动不会重复导入旧字段。

迁移前，程序在数据库旁的 `instance-group-backups/` 创建一致 SQLite 备份（包括尚在 WAL 内的写入），限制文件权限并验证完整性。迁移、数据回填和版本标记在同一事务中；格式无效、缺失关联、重名或循环会阻止迁移，不会静默删除数据。版本标记存在但关键关系表或唯一索引缺失时也会报错。

## API 与兼容字段

实例配置的 `groupIds: string[]` 是完整归属。`groupId` 和 `tags` 是由关系表派生的兼容输出，不应当作独立分类数据。

- 新客户端传入 `groupIds` 时，以该数组为准；`[]` 明确清空。ID 必须指向已有组，空白或不存在的 ID 会失败。
- 省略 `groupIds` 或传 `null` 时，旧 `groupId` 和 `tags` 只追加归属，保留未提及的组。旧标签写入按全目录唯一名称解析；需要新建时建立根组，同名有歧义时明确失败。
- 旧批量标签 `replace=true` 被拒绝，避免旧客户端覆盖其不了解的多组归属。旧移组接口是加入指定组，空 ID 不会清空关系。
- 新 Wails 接口 `BrowserProfileChangeGroups(profileIDs, groupIDs, mode)` 支持 `add`、`remove`、`set`，单次批量操作具有事务原子性。
- 分组目录读取使用 `BrowserInstanceGroupList`，读取失败会返回错误。旧 `ListGroups` 保留兼容入口。
- HTTP `POST /api/profiles`、`PUT /api/profiles/{id}` 的 `profile` 对象支持 `groupIds`。PUT 仍是完整配置更新，先读取当前配置并修改需要的字段。
- 启动、运行态与自动化 selector 的 `groupId` 匹配指定组及后代；旧 `tag/tags` 匹配唯一分组名称。名称、实例 ID、Code、关键字等条件按 AND 组合，不会因为 ID 已命中而跳过其余条件。

例如更新已读出的实例配置时：

```json
{
  "profile": {
    "profileName": "示例实例",
    "proxyId": "__direct__",
    "groupIds": ["existing-group-a", "existing-group-b"]
  }
}
```

上例只展示相关字段；实际 PUT 应携带需要保留的完整配置。API 返回的 `items[].groupIds` 可用于读取已有组 ID，创建与管理组使用实例列表界面。

## 导入、备份与恢复

实例包数据库格式升级为 2，携带所选实例的全部归属和祖先组；继续读取旧实例包和数据库格式 1。整库备份保留全部组，包括空组。导入根据身份和层级映射组 ID；与已有实例合并时，归属取并集。重复的同级名称、循环、缺失引用或有歧义的 ID 会拒绝整次导入。

旧筛选缓存只在分组目录成功读取后转换；无法解析的旧名称保留为未匹配条件，页面会提示，可手动清除。加载期间用户已经修改的条件会保留。

回滚需要配套恢复旧程序、迁移前数据库及配置，不能只降级二进制。升级后已有新增写入时，先备份当前状态并处理这些新增数据，不能直接覆盖。迁移备份是本地恢复点，不会上传到远程。
