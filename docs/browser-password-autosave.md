# Chromium 密码自动保存与更新

Linux 桌面应用运行时，受管理的 Chromium 实例会自动接受原生密码管理器的“保存密码”和“更新密码”提示。首次登录成功后保存凭据；同网站、同账号使用新密码登录成功后更新已有记录。密码仍由 Chromium 自己判断、加密和保存，各实例的密码库相互独立。

当前已在 Chromium 150.0.7871.186 验证。功能通过启动参数和仅作用于实例进程的环境变量启用原生无障碍控件接口，因此更新应用后新启动的实例可用；之前已经打开的实例需要按正常流程关闭后重新打开。软件不会为此强制重启实例。应用退出后自动确认暂停，再次启动应用会接管带相应启动参数的运行中实例。

仍遵守 Chromium 是否允许保存密码的设置、站点黑名单以及登录成功判断。浏览器没有产生保存/更新提示的情况（例如用户禁用保存、无痕窗口或网站未被识别为成功登录），不会由软件强行写入密码。无需再手动确认受支持的保存/更新提示，提示框可能短暂出现。

实现通过桌面 AT-SPI 总线操作原生按钮，校验实例数据目录、浏览器主进程和总线对象所属进程。指纹内核改写进程参数时，通过该实例的 SingletonLock 与 SingletonSocket 的实际监听进程确认归属。仅识别受支持语言的原生保存/更新密码提示，检查按钮状态，并跳过网页内容的无障碍子树。动作执行前再次确认实例仍在运行。每个提示最多提交一次，结果不明确时不重复点击。

软件不更改系统读屏设置或开放额外的浏览器控制端口。自动确认不抓取网页密码、不读取原生密码输入框、不直接操作 Chromium 的 Login Data 数据库，也不移动系统鼠标或激活浏览器窗口。Chromium 后续版本若改变内部界面接口，识别失败时保留原来的人工确认行为。

验证使用隔离 Xvfb、临时实例与本机合成账号。产品验证覆盖首次保存、更新不产生重复记录、实例隔离、网页伪造按钮不被点击、鼠标和焦点保持，以及仅退出应用后重启接管。
